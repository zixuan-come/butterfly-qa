## 当前工作项：V1 真实需求联调与微调

### 目标

核心代码、HTTP API 和 Web 工作台已经连通。下一步使用测试人员实际收到的产品需求走完整流程，根据真实产物质量微调 Agent Prompt、Skill 规则和输出模板。

### 本次范围

- 已固化“修改收货地址”需求样例及主成功路径测试。
- 已补充需求退回、用例退回、人工退回和证据缺失路径。
- 已验证 Agent 调用失败、重试、超时和人工接管。
- 已完成模块边界、运行方式、联调前置条件和 V1 限制的交接说明。
- 已完成统一 API 响应结构、文件大小限制、项目级写操作锁和路径安全检查。
- 已完成 Web 端项目管理、需求预览、产物展示、执行录入、证据上传和审批回退。
- 已通过真实浏览器验证“要求修改 -> 等待用例修订”闭环。
- 已实现 `butterfly-qa web` 单命令入口，前端静态资源随 Python wheel 分发。
- 已从临时 wheel 安装目录验证首页、静态资源和同源 API，无需 Node 运行时。

### 完成标准

- 主成功路径可以走到测试报告审批等待状态。
- 报告可追溯到需求、用例、执行记录和证据文件。
- 失败、退回、证据缺失和调用超时都有可诊断结果。
- Web 工作台可以完成 V1 的主要人工操作，不要求使用者记忆多条 CLI 命令。
- 不引入 RAG、数据库或接口自动化等 V1 外能力。

## 量化指标体系（待实施）

量化指标用于回答“Agent 产物是否真的提升测试质量和效率”，避免仅凭主观感受判断效果。该体系先记录，在真实需求联调阶段逐步实施。

| 指标 | 建议定义 | 主要评估阶段 |
| --- | --- | --- |
| 需求问题有效率 | 经产品或测试确认有效的问题数 / Agent 提出的问题总数 | 需求评审 |
| 需求问题误报率 | 被确认无效或无依据的问题数 / Agent 提出的问题总数 | 需求评审 |
| 测试点召回率 | Agent 命中的人工基准测试点数 / 人工基准测试点总数 | 测试设计 |
| 测试点准确率 | 经人工确认有效的测试点数 / Agent 生成测试点总数 | 测试设计 |
| 用例可执行率 | 无需修改即可执行的用例数 / Agent 生成用例总数 | 用例设计与评审 |
| 用例重复率 | 重复或高度相似的用例数 / Agent 生成用例总数 | 用例设计与评审 |
| 无依据扩展率 | 无需求、规则或设计资料依据的产物项数 / 产物项总数 | 全流程 |
| 评审问题命中率 | 用例评审 Agent 发现的有效问题数 / 人工确认问题总数 | 用例评审 |
| 人工修订耗时 | 测试人员检查和修改每阶段产物的实际耗时 | 全流程 |
| 端到端处理耗时 | 从需求导入到测试报告归档的总耗时 | 完整流程 |

实施原则：

- 首轮选择 1 至 3 个真实小需求，并由测试人员先建立人工基准。
- 同时记录分子、分母和具体问题，不能只填写百分比。
- 区分 Agent 原始产物与人工修改后的最终产物。
- 指标主要用于比较不同 Prompt、Skill 版本，不用于脱离样本规模宣传绝对效果。
- 样本不足时只记录观察结果，不提前得出稳定性结论。
